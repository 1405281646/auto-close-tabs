# 自动关闭标签页 · Vibe Coding 实战记录

一个 Chromium 浏览器扩展（Chrome / Edge，Manifest V3）：配置哪些网页在打开指定时间后自动关闭标签页。

## ① 项目背景

浏览器长期使用后标签页大量堆积（临时查资料、比价页、看一半的视频），手动逐个关闭效率极低，且经常忘了关。希望用 AI Agent 快速实现一个"指定网页打开 N 秒后自动关闭"的扩展，把这类机械操作彻底自动化。

## ② 开发方式声明

本项目通过 **Trae** 以 **vibe coding** 方式完成：

- **我负责**：需求定义（背景、规则语义、边界情况）、Prompt 迭代、代码审查、实际加载到浏览器中验证。
- **AI 负责**：生成初版实现（manifest、background service worker、选项页）。
- AI 不是"一次生成直接能用"，而是经过多轮"运行 → 发现问题 → 重新给约束"的循环才达到当前状态。③ 中的失败记录就是这些循环的真实沉淀。

## ③ AI Agent 失败场景记录

以下是开发过程中实际遇到的 AI 写错/偷懒的地方，以及我的纠正方式：

| # | 失败类型 | AI 的表现 | 发现方式 | 我的纠正 |
| --- | --- | --- | --- | --- |
| 1 | **AI 偷懒** | 初版只处理了当前活跃标签页（只监听激活页的状态变化），后台打开的标签页完全不受规则约束 | 实际运行：开一个后台标签页，倒计时不生效 | 在 Prompt 中给出明确的遍历约束：必须覆盖 `tabs.onCreated` / `onUpdated` 全部标签页，并在配置变化后调用 `chrome.tabs.query({})` 重扫所有标签页（对应 `background.js` 的 `resyncAllTabs`） |
| 2 | **边界情况遗漏** | 没有处理"固定标签页（pinned tabs）"的语义问题，也没有考虑窗口只剩最后一个标签页时被连锅端掉 | 测试中把窗口关到只剩一个标签页，整个窗口被自动关闭 | 要求 AI 补充防御逻辑：关闭前查询窗口内标签页数量，只剩一个时跳过（`background.js` 中 `tabs.length <= 1` 分支）；固定标签页则在"严格模式"行为约定中显式声明为无条件关闭，而不是含糊地不提 |
| 3 | **代码无法实际运行** | AI 初版用 `setTimeout` 实现倒计时，逻辑看似正确，但 MV3 service worker 空闲约 30 秒后会被浏览器挂起，挂起期间定时器回调不保证触发——超过 30 秒的规则时长全部静默失效 | 查阅 Chrome MV3 文档 + 实际设一个 60 秒规则验证，倒计时从未触发 | 要求改用 `chrome.alarms` 一次性闹钟（`when: Date.now() + delayMs`），闹钟触发时会唤醒 service worker。完整决策记录见 [ADR-0001](docs/adr/0001-alarms-for-countdown.md) |
| 4 | **表面完成** | AI 声称"已完成"，但排除列表优先级并未真正实现：命中排除项的页面仍会被关闭 | 实际运行：添加规则 `h5.ele.me` + 排除 `h5.ele.me/login`，登录页仍被关闭 | 在判定逻辑中显式要求"先匹配规则，再匹配排除项，命中排除项直接 return"，并对闹钟触发时刻的 URL 重新做双重校验（防止倒计时期间规则被改） |

这类问题直接对应岗位描述中的 reward hacking 行为：**假装完成任务、只做表面改动、输出无法实际运行的代码**。AI 的回答永远是"已完成 ✅"，唯一可靠的验收方式是把扩展加载进浏览器亲手跑一遍。

## ④ 验证方式

手动模拟以下场景逐项验证脚本行为：

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 多标签页（20+） | 批量打开 20+ 个命中规则的标签页，其中部分保持在后台 | 后台标签页同样按规则倒计时并关闭，不遗漏 |
| 固定标签页 | 固定一个命中规则的标签页 | 按严格模式约定：倒计时结束同样关闭（行为已在"行为约定"中显式声明，而非静默遗漏） |
| 单标签页 | 窗口只保留 1 个命中规则的标签页 | 跳过不关闭，窗口不会被自动清空 |
| 排除项优先 | 规则 `h5.ele.me` + 排除 `h5.ele.me/login` | 登录页不关闭，其余页面正常关闭 |
| 导航重置 | 倒计时进行中把标签页导航到不匹配的地址 | 旧倒计时取消，不误关 |
| 长时长规则（>30s） | 设置 60 秒规则并让浏览器后台空闲 | `chrome.alarms` 仍能唤醒 service worker 准时关闭 |

## 功能特性

- **规则配置**：按"域名 + 可选路径前缀"匹配网页，支持子域名
- **排除列表**：命中排除项的页面即使匹配规则也不会被关闭，优先级高于规则
- **倒计时时长**：全局默认 20 秒，每条规则可单独覆盖
- **右键快捷添加**：在任意网页上右键，一键把当前页面加入规则或排除列表
- **严格模式**：只要匹配规则，倒计时结束即无条件关闭标签页
- **安全保护**：窗口只剩最后一个标签页时跳过，不会自动关掉整个窗口
- **导航重置**：标签页跳转到新地址时按新 URL 重新评估倒计时
- **跨设备同步**：规则与排除项存于 `storage.sync`，登录同一浏览器账号即可同步

## 安装

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 开启右上角"开发者模式"
3. 点击"加载已解压的扩展程序"
4. 选择本项目文件夹（`auto-close-tab`）

## 使用

### 方式一：选项页配置

点击扩展图标 → 打开设置，或直接在 `chrome://extensions` 中点击本扩展的"详细信息"→"扩展程序选项"。

- **启用自动关闭**：总开关，关闭后所有规则暂停生效
- **全局默认倒计时**：未单独设置时长的规则使用此值（默认 20 秒）
- **规则列表**：查看和删除已有规则
- **添加规则**：填写域名（必填）和路径前缀（可选）、时长（可选）
- **排除列表**：查看和删除已有排除项
- **添加排除**：填写域名（必填）和路径前缀（可选），命中排除项的页面不会被关闭

### 方式二：右键菜单

在任意网页上右键：
- "把当前页面加入自动关闭规则"：当前页面（域名 + 路径）被加入规则
- "把当前页面加入排除列表"：当前页面（域名 + 路径）被加入排除列表，不再被自动关闭

## 规则匹配说明

| 输入 | 匹配范围 |
| --- | --- |
| `example.com` | `example.com` 及其所有子域名（`www.example.com`、`sub.example.com`）下的所有页面 |
| `example.com/watch` | 以 `https://example.com/watch` 开头的所有页面 |

- 匹配语义为"URL 以 域名+前缀 开头"
- 域名匹配包含子域名
- 仅匹配 `http` / `https` 页面
- **排除项优先**：页面命中规则时，若同时命中排除项则不关闭。例如规则 `h5.ele.me`（关闭全站）+ 排除 `h5.ele.me/login`（保留登录页），登录页不会被关闭

## 行为约定

- **严格模式**：倒计时结束后无条件关闭，不区分标签页是否激活、是否交互、是否固定、是否播放音频
- **末位标签页**：窗口只剩最后一个标签页时跳过不关闭
- **导航重置**：标签页 URL 变化时取消旧倒计时，按新 URL 重新评估

## 开发说明

- 倒计时使用 `chrome.alarms` 一次性闹钟实现（见 `docs/adr/0001-alarms-for-countdown.md`），保证 MV3 service worker 挂起后仍能可靠触发
- 权限：`tabs`（读取标签页 URL）、`storage`（规则存储）、`alarms`（倒计时）、`contextMenus`（右键菜单）
